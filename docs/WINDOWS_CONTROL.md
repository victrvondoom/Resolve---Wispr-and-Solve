# Windows control adapter

`src/windows_adapter.py` uses Win32 for live window identity and `SendInput` for real pointer and keyboard effects. It issues short-lived window snapshot IDs. A physical action may include the ID, which is refused after three seconds or if an observed foreground generation, PID, HWND, or window bounds change. The generation increments on observed foreground changes; a leave-and-return between observations may escape it. Coordinates must lie inside the target foreground window. Cursor moves recheck the foreground and detect unexpected movement. Input uses a process lock and a short cross-process `data/cursor.lock` file lock among RESOLVE processes. Emergency stop cancels further input between atomic `SendInput` calls.

The optional `capture_window()` captures a real screen crop of the selected foreground window using Pillow and stores the PNG plus SHA-256 evidence under `data/evidence`. It may contain overlapping popups; it is not a UIA semantic screenshot. Pillow is optional, and the rest of the app works without it. Win32 bounds and captures are subject to the process DPI context and multi-monitor scaling. Secure desktops, UAC, hidden/minimized windows, and higher-integrity targets are not bypassed.

Run `scripts/windows_demo.ps1` to create a controlled Tk window, move/click/type through the real OS input path, read the resulting widget state, and save one evidence screenshot. If Windows does not foreground the window automatically, click it within ten seconds. The test skips if the window cannot become foreground. The normal unit suite does not send physical input.

API references: [Microsoft INPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-input), [Microsoft SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow), [Microsoft DPI reference](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-reference), [Pillow ImageGrab](https://pillow.readthedocs.io/en/stable/reference/ImageGrab.html).
